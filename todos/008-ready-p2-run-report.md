# 008. 런 리포트

## Quest Card

- 목표: P1 한 판이 끝났을 때 도달 라운드, 처치한 보스, 흐린 패턴을 기록하기 쉽게 만든다.
- 플레이어 감정: “이번 테스트가 어디서 통과했고 어디서 막혔는지 알겠다.”
- 완료 보상: 플레이테스트가 기억이 아니라 자료로 남는다.
- 실패 신호: 승리/패배 화면이 결과만 말하고 다음 수정 힌트를 주지 않는다.

## Problem Statement

현재 게임오버/승리 화면은 기본 결과를 보여주지만, P1 라운드 진행과 적 패턴별 관찰을 비교할 수 있는 리포트는 없다.

## Findings

- `main.gd`는 wave, level, ore, weapons, items를 이미 알고 있다.
- P1에서는 계약 카드 기록이 필요 없다.
- 라운드 5 보스 처치 여부와 도달 라운드가 핵심이다.
- smoke playtest 출력은 최소 상태를 콘솔에 남긴다.

## Proposed Solutions

### A. 종료 화면 요약 확장

승리/패배 overlay에 무기, 아이템, 계약, 광석, 레벨을 더 선명하게 보여준다.

- 장점: 구현이 작다.
- 단점: 상세 분석은 어렵다.
- 노력: 낮음.
- 위험: 낮음.

### B. 콘솔/파일 로그 저장

런 종료 시 JSON 또는 텍스트로 결과를 저장한다.

- 장점: 여러 테스트 비교가 쉽다.
- 단점: UI에서 바로 보이지 않는다.
- 노력: 중간.
- 위험: 낮음.

### C. 개발자 대시보드 화면

게임 안에서 지난 런 목록과 퀘스트 상태를 보여준다.

- 장점: 가장 대시보드답다.
- 단점: 지금 단계에서는 관리 도구 구현이 너무 크다.
- 노력: 높음.
- 위험: 중간.

## Recommended Action

A로 시작하고, `--smoke-playtest`에는 B의 아주 작은 텍스트 출력만 붙인다. C는 나중에 필요할 때 승격한다.

## Acceptance Criteria

- [ ] 종료 화면에 도달 라운드와 보스 처치 여부가 보인다.
- [ ] P1 라운드별 주요 적 패턴이 런 결과에 포함된다.
- [ ] smoke playtest 출력이 도달 라운드/보스 처치 여부를 포함한다.
- [ ] 플레이테스트 메모로 옮기기 쉬운 한 줄 요약이 생긴다.
